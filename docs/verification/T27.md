## 設計

| 項目 | 說明 |
|---|---|
| 執行角色 | 分區以 Transport 的模型設定、備援次序與上限執行（`zoningSpec`，同樣依官方交通資料估算）；用量記錄為 Transport |
| 執行時點 | `research-job` 在研究、去重、核實、篩選之後分區；候選少於 2 個時略過 |
| 資料 | 新資料表 `zones`（成員可讀，啟用 RLS）；項目新增 `zone_id`、`zone_transfers`、`zone_minutes` |
| 寫入 | `apply_zoning`（只給 service_role，擁有者 `atps_verification_writer`）：取代行程現有的分區；項目必須屬於 job 的行程且尚未進入行程草案 |
| 畫面 | Candidate List 顯示分區名稱與「估算：轉乘 N 次，約 M 分鐘」 |

## 安全審查（S-15）

| 檢查 | 結果 |
|---|---|
| D29 | 送給 AI 的輸入不含 place_id、座標或任何 Google Maps 內容 |
| AI 輸出 | 嚴格 schema；未知或重複項目、圖片網址、API key 一律整份拒絕；只寫入分區，不改動行程 |
| 寫入範圍 | 函式只給 service_role；擁有者對 `zones` 有讀寫、對項目只有分區欄位與候選角色的更新權；使用者不可直接寫入 `zones` |
| 權限 | 沿用 `private.research_job_trip`；成員才能讀取分區（pgTAP 確認非成員讀不到） |

沒有發現可被利用的漏洞。
