## 設計

| 項目 | 說明 |
|---|---|
| 位置 | `packages/security`：`createAllowlistedFetch`（檢查邏輯）、`node-transport.ts`（Node 連線層）、`address.ts`（位址判斷）。只供伺服器端使用 |
| 白名單 | `packages/security/src/fetch-allowlist.json`，只能經 PR 修改；載入時驗證格式並凍結，執行期間不可變更。只接受完整主機名稱（小寫），不接受 IP、萬用字元、連接埠。本 Task 不加入網域，營運商與天氣來源於 T20、T22 經 PR 加入 |
| 網址檢查 | 只允許 https、443 埠；不可含帳號密碼；主機名稱必須完全符合白名單（子網域不算） |
| 位址檢查 | 拒絕私有、迴路、鏈路本地、CGNAT、文件、基準測試、多播與保留範圍。IPv6 只允許全球單播 2000::/3，並排除 Teredo、文件範圍；IPv4 對應位址與 6to4 依內嵌的 IPv4 判斷。無法解析的字串一律拒絕 |
| 防止 DNS rebinding | 連線層以 `lookup` 固定連到已驗證的位址，不再次解析主機名稱；連線後再比對實際位址 |
| redirect | 不自動跟隨；每次都重新檢查網址、白名單與 DNS 位址，上限 3 次 |
| 回應限制 | 時間上限 10 秒（含 DNS、連線與讀取）；大小上限 2 MB（先看宣告長度，再計算實際位元組，超過即中斷）；不接受壓縮；內容類型限 HTML、純文字、JSON、XML |
| 送出的標頭 | 只有 accept、accept-encoding、user-agent，不帶 cookie 或授權 |
| 結果 | 回傳 `{ ok: true, ... }` 或 `{ ok: false, reason, detail }`，不拋出例外 |
| CI | `pnpm test` 包含 SSRF 測試集；`ci.yml` 另列「SSRF 測試集」步驟（S-14） |

## 安全審查（S-15）

| 檢查 | 結果 |
|---|---|
| SSRF | 網址、白名單、DNS 位址在每一跳都檢查；連線固定到已驗證的位址，DNS rebinding 無法改變連線目標 |
