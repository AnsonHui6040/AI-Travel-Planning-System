## PASS 標準

| 標準 | 結果 | 證據 |
|---|---|---|
| 超過步數即停止 | PASS | `packages/core/src/role-runner.test.ts`：步數用完即停止，不再呼叫；超過 token 上限也停止並丟棄輸出；每次呼叫的輸出上限不超過剩餘 token |
| schema 不符的輸出被丟棄 | PASS | 同上：不符的輸出不回傳，只把問題欄位回饋給下一次呼叫；每次都不符時回傳 `output_invalid` 與欄位，結果不含輸出內容，並記錄用量。五個角色的輸出 schema 見 `packages/schemas/src/roles.test.ts` |

## 設計

| 項目 | 說明 |
|---|---|
| 五個角色 | `packages/ai/src/roles.ts`：系統提示、工具、資料範圍、記憶範圍、上限。輸出 schema 在 `packages/schemas/src/roles.ts`，送給 AI 的 JSON Schema 由 Zod 產生 |
| 工具（S-04） | Research：供應商內建搜尋。Verification：搜尋＋白名單 fetch。Transport：搜尋＋交通狀態。Master Planner、Live Planner：沒有工具。執行器只把供應商內建搜尋交給 AI；白名單 fetch 與交通狀態由伺服器取得後傳入（T16、T22） |
| 記憶範圍（MEM-11） | Verification 不讀記憶；Transport 只讀個人與單趟的限制；其餘依角色限定 |
| 輸出 schema（S-02） | 全部 strictObject：拒絕未知欄位（含圖片網址，S-16），來源至少一筆且必須是 https。Research 依 T24 的必填欄位；Planner 只輸出變更提案（S-01） |
| 執行器 | `packages/core/src/role-runner.ts`：依設定的順位呼叫，計算步數與 token，驗證輸出，記錄用量；沒有選模型或沒有 key 時不呼叫並提示（C-05） |
| 設定 | `ai_role_settings`（每人每角色一列）；沒有儲存的角色用決策 0006 的預設值。檢查：步數 1–100、token 1,000–1,000,000、備援 1–3 家不重複、模型名稱格式 |
| 模型清單 | 設定頁以使用者本人的 key 取得三家可用模型（Gemini 只列可產生內容的模型），作為模型欄位的選項 |
| 用量（S-06） | `ai_usage` 記錄每次執行的角色、供應商、模型、步數、token 與結果；設定頁顯示近 30 日每個角色的加總 |
| 權限 | 兩張表都只限本人；用量紀錄不可修改或刪除；未登入不可讀取 |
| 設定頁 | `/settings/ai`：五個角色各一組，三個順位的供應商與模型、兩個上限、儲存；同一家警告；用量表 |

## 安全審查（S-15）

| 檢查 | 結果 |
|---|---|
| 工具權限 | 角色工具清單固定；執行器不把伺服器端工具交給 AI；adapter 拒絕清單以外的工具 |
| 輸出 | 一律以 strict schema 驗證，不符即丟棄；回傳結果與紀錄不含不合格的內容 |
| 上限 | 步數與 token 由伺服器計算，超過即停止；上限值在應用程式與資料庫兩處檢查 |
| key | 模型清單只用請求者本人的 key；沒有 key 時不呼叫；錯誤訊息固定 |
| 權限 | 設定與用量只限本人（RLS，pgTAP）；擁有者取自 session，忽略表單欄位 |
| 故障 | 不自動切換到其他供應商（C-08） |

沒有發現可被利用的漏洞。
