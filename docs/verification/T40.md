## 設計

| 項目 | 說明 |
|---|---|
| 需要標記的項目 | 排入過某一天，或有 Actual Timeline 紀錄（含計畫外的 Backup）。從未排入、沒有紀錄的候選不標記 |
| 可選狀態 | 實際去過（最後一筆紀錄為完成，與 T39 相同）：完成、想再去、不推薦。沒有去過：略過、取消、想再去。core 的 `allowedPostTripStatuses` 與資料庫 `set_post_trip_status` 使用同一規則 |
| 寫入 | `set_post_trip_status`（擁有者 `atps_change_writer`，Owner、Companion；行程須為已結束）；回傳尚未標記數，為 0 時行程進入已封存 |
| 報告 | core 的 `postTripReport`（純函式），輸入為各日保存的 Planned vs Actual（T39）、旅後狀態與採用的交通估算（T28）。停留時間差異：有到達與離開的排定項目。交通估算差異：當天有實際時間的相鄰兩站（含部分完成），以前一站離開到下一站到達計算，沒有估算時不列入。實際用上的 Backup：計畫外且完成。過密時段：晚到 30 分鐘以上、部分完成或停留不到排定一半的相鄰排定項目合併為一段。證實不可靠的建議：旅後標示不推薦，附產生者 provider 與模型（使用者新增者標示）。最喜歡的活動類型：想再去 2 分、完成 1 分、不推薦扣 1 分，只列正分 |
| 記憶 | 報告不寫入記憶（MEM-03）；T41 以這份報告產生旅後記憶提案，由擁有者批准 |
| 畫面 | `/trips/[tripId]/post-trip`；Actual Timeline 產生後顯示入口。Viewer 只能閱讀 |
