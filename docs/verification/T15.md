## 設計

| 項目 | 說明 |
|---|---|
| 場景格式 | `evals/scenarios/<編號>.json`，以 Zod 嚴格驗證（`evals/src/scenario.ts`）：編號、標題、對應規則、角色、執行次數（預設 5）、給 AI 的指示、行程資料、判定器。判定器引用不存在的項目、未知欄位或未知判定器時拒絕 |
| 錄製回應 | `evals/recordings/<編號>.json`，第 n 次執行使用第 n 筆，不足時循環。E6 的回應是依 Live Planner 輸出 schema 撰寫的合成資料 |
| 執行 | 每次都經 core 的 `runRole`：與正式執行一樣驗證輸出 schema、計算步數與 token。不符 schema、超過上限、供應商故障時，該次判定不通過並記錄原因，不執行判定器 |
| 判定器 | `evals/src/judges.ts`，只看 AI 輸出的變更提案與場景資料，不呼叫 AI：`within_window`（只動同一時段）、`dates_unchanged`、`items_preserved`（標示 At Risk 不算移動）、`only_candidates`、`requires_approval`（依第 2.6 節批准規則）、`change_kind`、`proposal_count`，以及每次都執行的 `known_items` |
| 重複執行 | 依場景的執行次數連續執行，全部通過才算通過（第 9.1 節） |
| 報告 | `evals/src/report.ts`：規則、日期、模式、角色、執行次數、結果；每次的狀態與未通過的判定；未通過明細。錄製回應的報告不列供應商，避免誤認為真 AI 結果 |
| 指令 | `pnpm evals:run`（全部場景）；`EVAL_SCENARIOS=E6 pnpm evals:run`（指定場景）。不納入 `pnpm test`，CI 以 `evals/src/*.test.ts` 驗證 runner 與判定器 |

## 安全審查（S-15）

| 檢查 | 結果 |
|---|---|
| key | 錄製回應不呼叫供應商，使用固定的假憑證；runner 不讀取環境變數中的 key。以真 AI 執行時經 `roleInvoker` 傳入伺服器端的 deps，key 只取使用者本人的（C-05） |
| 輸出 | 不合格的輸出不進入判定器，報告只記錄原因與欄位，不記錄內容（S-02） |
| 寫入 | runner 只讀取場景與錄製回應，只寫入 `docs/verification/evals/` 的報告；不寫入資料庫 |
| 輸入 | 場景與錄製回應以嚴格 schema 驗證；報告中的文字會跳脫表格分隔符號 |
