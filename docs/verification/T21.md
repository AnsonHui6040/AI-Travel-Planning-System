## 設計

| 項目 | 說明 |
|---|---|
| 移除 EXIF（S-09） | `sanitizeImage`（`packages/security`）：依檔頭判斷實際格式，只接受 JPEG、PNG、WebP，上限 5 MB。不解碼影像，只保留影像所需的區段：JPEG 移除 APP1–APP15 與 COM，EOI 之後的資料捨棄；PNG 只保留影像與色彩區塊；WebP 只保留影像區塊並清除 VP8X 旗標、重算長度。結構不完整的檔案拒絕。沒有新增依賴 |
| 壓縮 | 瀏覽器端把大於 1.5 MB 或長邊超過 2048 的照片縮小並重新壓縮為 JPEG。EXIF 一律由伺服器移除，不依賴瀏覽器 |
| 上傳路徑 | Server Action 依序檢查登入、速率限制、角色（Owner、Companion，第 6 節）、項目屬於該行程，移除 EXIF 後以 service role 上傳到不公開 bucket `trip-photos` 的行程資料夾，再以使用者 session 寫入紀錄（受 RLS 限制）；紀錄寫入失敗時刪除檔案 |
| Storage 權限 | 使用者（包括 Owner）沒有上傳、修改或刪除物件的權限，必須經伺服器移除 EXIF；成員可讀取自己行程資料夾的照片，非成員讀不到 |
| 顯示 | 照片由同源的 `/api/photos/…` 提供（登入、Origin、速率限制；成員資格由 Storage RLS 判斷），CSP 不需放寬。使用者照片標示拍攝者；Commons 照片標示作者、授權與 Commons 連結（`rel="noopener noreferrer"`） |
| Commons（D14） | 授權限 CC0、CC BY、CC BY-SA 或公有領域；作者必填；來源必須是 `commons.wikimedia.org/wiki/File:` 網址。`parseCommonsAttribution`（`packages/schemas`）與資料庫 check 使用相同規則 |
| 沒有照片 | `photoDisplay` 顯示當地名稱（沒有時用中文名稱）與地址 |
| 資料庫限制 | 照片的項目必須屬於同一行程；Storage 路徑必須是「行程編號/照片編號.副檔名」且在本行程資料夾 |

## 安全審查（S-15）

| 檢查 | 結果 |
|---|---|
| EXIF | 伺服器依結構只保留影像所需區段；使用者無法直接寫入 Storage 繞過 |
| 檔案類型 | 依檔頭判斷，不信任上傳時宣告的類型；SVG、HTML、GIF 拒絕；回應帶 `x-content-type-options: nosniff` |
| 路徑 | 伺服器產生路徑；資料庫限制路徑格式與行程資料夾；讀取路徑先比對格式 |
| 權限 | 上傳限 Owner、Companion；讀取限成員；service role 只用於寫入已處理的檔案 |
| 大小 | 5 MB 上限（bucket 與伺服器各自檢查），Server Action 請求上限 6 MB |

沒有發現可被利用的漏洞。
