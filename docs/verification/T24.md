## 設計

| 項目 | 說明 |
|---|---|
| 研究方向 | `RESEARCH_TRACKS`（`packages/core/src/research.ts`）：A 主要景點與官方資訊、B 餐飲咖啡購物、C 攝影與季節活動、D 冷門替代 |
| 獨立性 | 每個方向以同一份行程與基線資料組成輸入（`composeRoleInput` 資料區塊，S-03），只有工作說明不同；不讀 Candidate List，也不讀其他方向的輸出 |
| 背景 job | `apps/web/workflows/research-job.ts`：job 狀態設為執行中後，四個方向各為一個 step 以 `Promise.all` 平行執行；至少一個方向寫入候選時 job 為完成，否則為失敗。step 只以 job 編號重新讀取資料，只解密 job 發起人的 key（C-12） |
| 開始研究 | Server Action `startResearchAction`：登入、速率限制（每 10 分鐘 5 次）、行程成員為 Owner 或 Companion、行程已確認基線（規劃中、已鎖定、進行中）、Research 第一順位已選模型且發起人有該家 key，全部通過才建立 job |
| 寫入 | 資料庫函式 `add_research_candidates`（只給 service_role，擁有者 `atps_candidate_writer`，只有 `itinerary_items` 新增權）：檢查 job 為執行中的研究 job、發起人仍為 Owner 或 Companion、行程已確認基線；方向只限 A–D；每次 1–30 個。生命週期固定為候選、核實狀態固定為 Unverified；篩選分數與優先度先填 0 與 3，於 T26 評分 |
| 重試 | 同一 job 同一方向已寫入時回傳 0，workflow step 重試不會重複寫入 |
| 新欄位 | `itinerary_items.research_track`（A–D）、`research_job_id`（成員自行加入的項目為 null） |
| 畫面 | `/trips/[tripId]/candidates`：依研究方向分組，每個候選顯示地區、類型、停留、核實狀態、是否已對應 Google 地點、推薦原因與限制（`SafeMarkdown`）、來源（`SafeLink`、來源等級、取得時間）與產生的模型。候選不會自動排入行程 |

| TSX 單元測試 | `vitest.config.ts` 設 `oxc.jsx.runtime: "automatic"`（`apps/web` 的 tsconfig 為 `jsx: preserve`） |

## 測試順序

先新增 `packages/core/src/research.test.ts`、`packages/core/src/safe-markdown.test.ts`、`apps/web/lib/server/research-core.test.ts`、`apps/web/components/safe-markdown.test.tsx` 與 `supabase/tests/14_research_candidates.test.sql`，執行確認失敗（RED：單元測試 41 項失敗、兩個測試檔模組不存在；pgTAP 計畫 18 項執行 0 項）。實作後通過（GREEN）。

實作中調整的測試與程式：

1. 裸露網址自動轉為連結時，`src="https://…"` 這類屬性值中的網址也被轉成連結。改為前一個字元是引號或等號時不轉換，由「HTML 標籤只當文字」的測試確認。
2. 元件測試原本以 `\sonerror=` 判斷，轉義後的文字也會符合。改為只檢查標籤內的 on 屬性。
3. 加入 research workflow 後 `pnpm test:workflow` 的 4 個既有測試失敗（bundle 載入工作區套件失敗），加入上述測試環境 hook 後通過。

## 安全審查（S-15）

| 檢查 | 結果 |
|---|---|
| 寫入範圍 | AI 輸出只經 `handleRoleRun` 的去處寫入候選；資料庫函式只給 service_role，擁有者只有 `itinerary_items` 的新增權，policy 限制只能新增 Unverified 的候選且必須帶 job 編號 |
| 權限 | 開始研究前以使用者 session 檢查成員角色；背景 step 與資料庫函式各自再檢查 job 種類、狀態、發起人角色與行程狀態，發起人被移除或降為 Viewer 後不再寫入 |
| API key | step 只經 `decrypt_job_api_key` 取得 job 發起人的 key（C-12）；發起人的 AI 與 Google Maps key 列為禁止輸出的值，輸出含有時整份拒絕 |
| Prompt injection | 行程與基線（含成員填寫的體力限制、攝影需求）以資料區塊傳入（S-03）；各方向不讀其他 AI 的輸出 |
| 輸出呈現 | 不使用 `dangerouslySetInnerHTML`；Markdown 只解析成有限結構，連結只允許 https 並加 `rel="noopener noreferrer"`；來源網址同樣經 `SafeLink` |
| 圖片 | AI 輸出含圖片網址時整份拒絕；畫面不顯示 AI 提供的任何圖片 |
| 費用 | 開始研究每 10 分鐘 5 次；每個方向沿用 Research 的步數與 token 上限（決策 0006） |
| 回應與 log | Server Action 只回傳訊息；log 不含行程、基線或 AI 輸出內容 |

沒有發現可被利用的漏洞。
