## 設計

| 項目 | 說明 |
|---|---|
| 快照 | `versions.snapshot`：版本寫入時由 BEFORE INSERT trigger 記錄行程所有項目的日期與時間。`commit_proposal`、`restore_version` 以及之後新增的寫入路徑都會自動記錄 |
| `restore_version` | 資料庫函式，以 `atps_change_writer` 身分執行：檢查 Owner 或 Companion、鎖行程列、比對 base version，把有差異的項目改回快照，建立新版本並通知其他成員（`version_restored`） |
| 版本類型 | 與第 2.7 節相同：有項目換日或影響兩天以上為 Major，其餘為 Minor |
| 復原範圍 | 只復原排程。At Risk 屬事實資料，復原後保留；所選版本之後才排入的項目改回未排程 |
| 沒有差異 | 行程已與所選版本相同時拒絕（22023），不建立空版本 |
| 舊紀錄 | 沒有快照的版本拒絕復原（22023） |
| core | `restorePreview` 列出復原會改動的項目與版本類型，供確認畫面使用；`restoreVersion` 檢查後交給 `VersionRestorer` |
| db | `SupabaseVersionRestorer` 呼叫 `restore_version`，錯誤訊息不外洩 |

## 安全審查（S-15）

| 檢查 | 結果 |
|---|---|
| 權限 | 復原者取自 session，不接受呼叫者傳入；只有 Owner、Companion 可復原；不存在與沒有權限的版本回應相同（42501），不洩漏版本是否存在 |
| 跨行程 | 行程由版本列推得，只改動同一行程的項目 |
| 並行 | 先鎖行程列再比對 base version，與 `commit_proposal` 次序相同，避免死結與覆蓋他人變更 |
| 寫入角色 | `restore_version` 擁有者為 `atps_change_writer`，沿用 T09 的欄位權限；authenticated 仍不可直接寫入正式行程表 |
| 函式權限 | 只授權 authenticated 執行 `restore_version`；trigger 函式收回所有執行權限 |
| search_path | 新函式都設 `search_path = ''` |
| core 依賴 | `restore.ts` 只 import `@atps/schemas`（M-01） |

沒有發現可被利用的漏洞。
