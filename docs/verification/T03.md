## 測試順序

1. 先寫 3 個 pgTAP 檔，尚未建立 migration：`Result: FAIL`（RED）。
2. 建立 migration 後，未登入讀取改為直接被拒（42501），比原預期的回傳 0 筆更嚴格，因此修改測試預期；子查詢不能包含 DML，改用測試 transaction 內的 helper 計算影響筆數。之後 39 個測試全部通過（GREEN）。
3. 先寫 `apps/web/lib/server/guard.test.ts`：模組不存在而失敗（RED）；實作後 25 個單元測試全部通過（GREEN）。

## 資料庫設計

| 項目 | 內容 |
|---|---|
| 表 | `public.profiles`（新使用者由 trigger 建立）、`public.trips`、`public.trip_members`（每個行程只有一個 Owner，以 partial unique index 保證） |
| helper | `private.trip_role_of`、`is_trip_member`、`is_trip_owner`、`shares_trip_with`：security definer，`search_path = ''`，避免 policy 互相遞迴 |
| 行程內容修改 | 不開放直接 update，經提案與 `applyChange`（T09） |
| Owner 轉移 | `public.transfer_trip_ownership`：只有目前 Owner，對象須為成員 |
| 速率限制 | `public.check_rate_limit`：固定時間窗，計數存於不公開的 `private.rate_limit_counters` |
| 權限 | `anon` 對三張表沒有任何權限；`private` schema 不經 PostgREST 公開 |

## C-11 共用元件

`apps/web/lib/server/guard.ts`：依序檢查 Origin（403）、登入（401）、速率限制（429）。寫入請求一律要求 Origin；沒有 Origin 的 GET 以 `Sec-Fetch-Site` 判斷。`apps/web/lib/server/supabase.ts` 以請求者本人的 session 呼叫資料庫，只使用 anon key（C-09）。
