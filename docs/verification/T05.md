## 發現

| 項目 | 說明 |
|---|---|
| workflow ID | 測試端與 builder 都以啟動目錄計算 workflow ID，`pnpm test:workflow` 必須在 repo 根目錄執行；vitest 不可另設 `root` |
| 取消後的讀取 | Local World 中取消後 `returnValue` 不會結束，進度串流也未關閉；測試改以輪詢狀態並在閒置後停止讀取 |
| 失敗時的串流 | 以 `try/finally` 關閉進度串流，失敗時讀取端才會結束 |
| 安裝腳本 | `@swc/core`、`esbuild`、`cbor-extract` 以 `allowBuilds: false` 明確不執行安裝腳本（S-11），預建二進位檔由 optionalDependencies 提供 |
| 示範端點 | `POST /api/jobs/spike` 經 C-11 guard；預設關閉 |
| 依賴漏洞 | PR #9 第一次 CI 被「依賴漏洞」關卡擋下：`workflow > @workflow/cli > @vercel/cli-auth` 鎖定 `zod` 4.1.11（GHSA-mrhx-c7xc-m3w5，high）。以 pnpm overrides 將 `zod@<4.6.6` 改為 4.6.7，重新 audit 後只剩 1 個 moderate |

## 安全審查（S-15）

| 項目 | 結果 |
|---|---|
| 示範端點 | 預設回應 404；開啟時仍需登入、Origin 相符與速率限制；發起人取自 session，不接受請求內容指定 |
| job 狀態與取消 | 未提供端點；待 T06 背景 job 資料表可核對發起人後再加入，避免以 runId 存取他人 job |
| 安裝腳本 | 新增依賴的安裝腳本全部不執行 |

沒有發現可被利用的漏洞。
