## 設計

| 項目 | 說明 |
|---|---|
| 記錄 | Owner、Companion 以本人 session 寫入 `actual_timeline_entries`（T06 的 RLS：本人名義）。新增 trigger `check_actual_timeline_entry`：項目須屬同一行程、時間不晚於現在（容許 5 分鐘）、該日尚未完成。同一項目可多次記錄，以最後一筆為準 |
| 計算 | core 的 `actualTimeline`（純函式）：排定項目依排定開始排序；沒有排定、但實際時間（目的地時區）落在當天的項目列為計畫外；只有「完成」為已去過；摘要只計排定項目 |
| 產生 | Server Action 以使用者 session 讀取並計算後呼叫 `produce_actual_timeline`（擁有者 `atps_change_writer`，Owner、Companion；行程已鎖定或進行中；該日已批准、Day Ready 或進行中）。資料庫以紀錄重新判斷已去過，不採用送出內容；保存於 `days.actual_timeline`（上限 32 KB）、產生時間與產生者；通知其他成員（`timeline_produced`） |
| 生命週期 | 只有最後一筆為完成、且標為已去過的項目由已鎖定（或已批准、已修改、變更提案中）進入已完成；部分完成、略過與沒有紀錄的項目不變，交給 T40 的旅後狀態標記 |
| 畫面 | `/trips/[tripId]/timeline`；當日行程新增入口。產生前為預覽，不顯示「已去過」標示；計畫外可選 Backup 與 Standby 記錄。Viewer 只能閱讀 |

## 安全檢查（S-15）

| 項目 | 結果 |
|---|---|
| 權限 | 記錄與產生只限 Owner、Companion；Viewer 被拒（pgTAP）；authenticated 沒有 `days` 的 UPDATE |
| 跨行程 | trigger 拒絕記錄其他行程的項目（T06 的 policy 只檢查行程，這次補上項目檢查） |
| 已去過 | 由資料庫依紀錄判斷，伺服器或直接呼叫 RPC 送出的內容無法把未完成的項目標為已完成 |
| 保存內容 | Planned vs Actual 由伺服器計算，以 React 呈現（自動跳脫）；大小上限 32 KB。直接呼叫 RPC 的成員可改動保存的文字內容，但不影響項目狀態，與 Morning Check 結果的處理方式相同 |
| 個人資料 | 只保存紀錄者的使用者 ID，不含姓名、電話、電子郵件 |
