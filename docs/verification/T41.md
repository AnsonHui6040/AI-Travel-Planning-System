## 各規則

| 規則 | 實作 |
|---|---|
| MEM-01 | 三層（個人偏好、Planning Rules、單趟旅行）。`/settings/memories` 依三層管理；單趟記憶在 `/trips/[tripId]/memories` 新增 |
| MEM-02 | T06 的欄位；來源提案編號改指向 `memory_proposals`，並檢查來源與編號一致 |
| MEM-03 | 寫入途徑：本人 session 手動（RLS own_all，來源只能是 manual）；旅後提案經 `decide_memory_proposal` 由本人批准（擁有者 `atps_memory_writer`）。撤銷 service_role 的寫入權 |
| MEM-04 | `@atps/memory` 的 `postTripMemoryProposals` 依 T40 比較報告產生 Planning Rules 提案（停留時間調整、交通估算額外緩衝、Backup 實際使用、每日安排密度、不可靠的建議來源（provider 與模型）、喜歡的活動類型），有門檻（停留平均差 15 分鐘、交通平均差 10 分鐘）。旅後回顧頁「產生旅後記憶提案」，每位成員各自為本人建立 |
| MEM-05 | 記憶存於本系統；三家 AI 收到同一份合併結果 |
| MEM-06 | 本人可修改、刪除；刪除後不再讀出、不再送出 |
| MEM-07 | 合併所有目前成員；trigger `check_memory_write` 與 `private.identity_violation` 拒絕身分與聯絡資料（與 `identityViolation` 同一規則） |
| MEM-08 | 決策 0009；畫面標示「成員間有不同設定，已取最保守值」，不顯示成員 |
| MEM-09 | 只讀目前成員的記憶；成員離開時 T32 的 trigger 刪除其該行程記憶 |
| MEM-10 | 單趟 context 只在該行程讀出 |
| MEM-11 | `memoryBlockContent` 依角色 `memoryScope` 輸出；Research 以 member_preference 資料區塊送出（S-03） |

## 安全檢查（S-15）

| 項目 | 結果 |
|---|---|
| 寫入權 | 記憶只經本人 session 或本人批准的提案寫入；service_role 與 AI 輸出都無法寫入 |
| 讀取 | `trip_memories` 只限成員，不回傳擁有者；記憶只限本人直接讀取（T06 RLS） |
| 提示注入 | 記憶屬成員自由文字，放在資料區塊（S-03） |
| 個人資料 | 身分與聯絡資料在資料庫層拒絕，不依賴畫面 |
| 提案 | 成員只能為本人建立、決定提案；提案內容與手動新增的權限相同 |
