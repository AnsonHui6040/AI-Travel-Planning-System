## 設計

| 項目 | 說明 |
|---|---|
| 範圍 | 敏感欄位依「行程 × 成員」儲存（SH-07：移除成員時刪除其在該行程的資料）。只有全名、電話、電子郵件三個欄位，不收集護照與身分證字號 |
| 儲存 | `member_sensitive_fields` 只存 Vault secret 編號與三個開關，沒有明文欄位；值以 Supabase Vault 加密。刪除紀錄（清空、移除成員、刪除行程、刪除帳號）時以觸發器刪除 Vault secret |
| 存取 | 使用者只經資料庫函式：`save_sensitive_field`、`set_sensitive_sharing`、`list_trip_sensitive_fields`。函式以 session 的使用者判斷當事人與角色，不接受呼叫者傳入的使用者編號；直接寫入資料表被拒。函式擁有者 `atps_pii_keeper` 只有 Vault 與本表所需權限 |
| 開關 | 「提供給 AI」、「提供給其他成員」（Owner、Companion）、「提供給 Viewer 與唯讀連結」，預設關閉，只有當事人可以修改 |
| 格式 | 全名 1–80 字、不可含換行；電話只可含數字、空白、括號、連字號與開頭的 +，數字 6–15 位；電子郵件 ≤254 字元。`packages/schemas` 的 `parseSensitiveValue` 與資料庫 `private.valid_sensitive_value` 使用相同規則，錯誤訊息不含輸入值 |
| AI payload | 伺服器以 service role 呼叫 `ai_sensitive_fields`（只授權 service_role，只回傳開啟「提供給 AI」的欄位，請求者須為 Owner 或 Companion）。`buildAiPayload`（`packages/security`）以 allowlist 只帶出明列的行程與項目欄位，成員以 M1、M2 代號識別，付款人轉為代號；再次檢查 `shareAi` |
| Google 內容 | payload 不含 place_id、地址、座標、當地名稱（S-17 的一部分）。項目名稱來源與評分、照片、路線的排除於 T19 |
| log 遮罩 | `createLogger` 每行寫出前以 `redactSensitive` 遮罩 API key、已知的敏感欄位值，以及電子郵件與電話格式。Server Action 失敗時經此 log；回應訊息固定，不含值 |
| AI 請求紀錄 | `ai_usage` 只記錄角色、供應商、模型、步數、token 與結果，不含請求或回應內容 |
| 畫面 | `/trips/[tripId]/my-info`：當事人輸入三個欄位與開關；下方列出其他成員開放給自己的資料。非成員顯示找不到行程 |

## 安全審查（S-15）

| 檢查 | 結果 |
|---|---|
| 權限 | 他人的值只在當事人開啟對應開關時回傳；開關只有當事人能改；非成員不能儲存也查不到；Viewer 與非成員不能取得 AI 用的欄位 |
| 加密 | 值只存在 Vault；`authenticated` 不能讀 `vault.decrypted_secrets`，也不能直接寫入資料表 |
| 使用者身分 | 函式只取 session 的使用者，表單不傳使用者編號 |
| AI | payload 由 allowlist 產生，輸入物件多出的欄位不會帶出；三家請求快照不含未開放的值與使用者編號 |
| 外洩 | 回應訊息、資料庫錯誤與 repository 錯誤固定，不含值；log 寫出前遮罩 |

沒有發現可被利用的漏洞。
