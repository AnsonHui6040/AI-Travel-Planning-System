## 修正紀錄

第一次執行時，PR #4 的 gitleaks 也失敗。原因是 `fetch-depth: 0` 取得所有分支，gitleaks 預設掃描全部分支，因此 PR #3 分支上的假 secret 讓 PR #4 一起失敗。已改為 `--log-opts="HEAD"`，只掃描此分支可達的 commit。改完後在本機驗證：vuln 分支沒有發現洩漏，假 secret 分支發現 1 筆；CI 重跑結果如上表。
