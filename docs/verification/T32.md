## 設計

| 項目 | 說明 |
|---|---|
| 邀請連結 | `create_trip_invitation`（只限 Owner，角色只能 Companion 或 Viewer）產生 256 位元隨機 token，只回傳一次；資料庫只保存 SHA-256。7 天到期、只能使用一次、可撤銷；每個行程最多 20 個有效邀請 |
| 加入 | 受邀者以本人登入後開啟 `/invite/<token>`：`invitation_preview` 只在連結有效時回傳行程名稱與角色（無效時不說明原因），`accept_trip_invitation` 加入並標記已使用。頁面設定 `referrer: no-referrer`，連結不經 Referer 外流 |
| 不可直接加入 | 收回 authenticated 對 `trip_members` 的 INSERT（T03 原本允許 Owner 直接加入任何使用者編號）；成員只經受邀者本人接受加入 |
| 角色變更、移除、退出 | 沿用 T03 的 RLS：只有 Owner；不可改為或移除 Owner（轉移經 `transfer_trip_ownership`）；Companion、Viewer 可自行退出 |
| SH-07 | trigger `cleanup_removed_member`：刪除該成員在此行程的行程記憶（`trip_context`）與通知；敏感欄位與 Vault secret 由 T17 的外鍵 cascade 與 trigger 刪除；個人記憶保留。記憶合併以目前成員名單決定，移除後不再合併 |
| SH-03 | 加入行程不取得他人 key 的使用權；AI 動作一律以發起人本人的 key 執行（T12、T24），排程 job 只在 Owner 開啟時使用 Owner 的 key（T31） |
| 畫面 | `/trips/[tripId]/members`：成員與角色、Owner 的角色變更與移除（移除前確認）、邀請連結與狀態、撤銷；非 Owner 顯示退出按鈕 |

## 安全審查（S-15）

| 檢查 | 結果 |
|---|---|
| token | 256 位元隨機值，無法列舉；只存 SHA-256，Owner 也讀不到雜湊（欄位權限，pgTAP）；只顯示一次 |
| 未經同意加入 | Owner 不能直接新增成員（pgTAP）；只有受邀者本人能接受 |
| 越權 | 邀請、撤銷只限 Owner；接受只能以邀請的角色加入，不能成為 Owner；已是成員、過期、撤銷、已使用一律拒絕 |
| 資訊洩漏 | 未登入看不到行程名稱；無效連結不說明原因；邀請頁不送出 Referer |
| 移除後存取 | 被移除者看不到行程與成員（RLS），進行中的研究 job 在 step 檢查發起人仍為成員 |

沒有發現可被利用的漏洞。
