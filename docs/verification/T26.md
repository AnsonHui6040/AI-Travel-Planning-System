## 設計

| 項目 | 說明 |
|---|---|
| 評分方式 | 確定性規則（`screenCandidates`），不呼叫 AI；規則見 `docs/decisions/0007-candidate-screening.md`。計畫沒有指定評分方式，依使用者「用量 95% 前不必詢問」的指示先行決定，標為暫定 |
| 執行時點 | `research-job` 在研究、去重、核實之後評分所有尚未排入行程的候選（候選、待核實、已核實），一次寫入 |
| 寫入 | 資料庫函式 `apply_candidate_scores`（只給 service_role，擁有者 `atps_verification_writer`，新增八個維度、候選角色、優先度與天氣依賴度的更新權）；檢查研究 job、發起人權限與行程狀態，項目必須屬於該行程且尚未進入行程草案 |
| 畫面 | Candidate List 每個候選顯示候選角色與八個維度（390 寬度兩欄、1280 寬度四欄） |

## 安全審查（S-15）

| 檢查 | 結果 |
|---|---|
| 寫入範圍 | 函式只給 service_role；擁有者只增加評分相關欄位的更新權；值域由欄位約束檢查 |
| 權限 | 沿用 `private.research_job_trip`：研究 job 執行中、發起人為 Owner 或 Companion、行程已確認基線；項目必須屬於該行程 |
| 輸入 | 評分由伺服器計算，不經 AI 或使用者輸入；陣列上限 500 |
