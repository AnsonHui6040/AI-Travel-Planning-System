# 0009 記憶限制衝突取最保守值的規則

| 項目 | 內容 |
|---|---|
| 狀態 | 已決定 |
| 日期 | 2026-11-27 |
| 決定者 | 使用者 |
| 相關 | 計畫第 5 節 MEM-07、MEM-08、第 11 節、T41 |

記憶的「項目」原為自由文字，無法判斷哪個值較保守。採用固定限制清單：每項定好單位與保守方向。

| 限制項目 | 單位 | 最保守 |
|---|---|---|
| 每日步行上限 | 公里 | 取最小 |
| 單次連續步行 | 分鐘 | 取最小 |
| 每日活動時數 | 小時 | 取最小 |
| 每日轉乘上限 | 次 | 取最小 |
| 休息間隔 | 分鐘 | 取最小 |
| 每日預算上限 | 幣別（例如 JPY） | 同幣別取最小，不同幣別全部保留 |
| 最早出發 | HH:MM | 取最晚 |
| 最晚回住宿 | HH:MM | 取最早 |
| 飲食限制 | 清單 | 全部保留 |
| 清單外的限制 | 文字 | 全部保留 |

- 清單內的限制在新增時檢查格式（數字或 HH:MM），單位以清單為準。
- 數值無法判讀的舊資料保留原值，不參與比較。
- 有衝突時畫面標示「成員間有不同設定，已取最保守值」，不顯示是哪位成員。
- 偏好不合併，全部保留（相同的只留一個）。

實作：`packages/memory/src/merge.ts` 的 `CONSTRAINT_CATALOG` 與 `mergeMemories`。
