## 3. 功能規格

### E 行程編輯

| 項目 | 規格 |
|---|---|
| 手動新增 | 名稱、類型、地址（可空）、建議停留、日期與時間（可空，空則進候選清單）、備註；來源為「使用者新增」 |
| 核實狀態 | 使用者新增的項目為「使用者確認」：可被排入每日行程，畫面標示來源；不經 AI 核實，也不會被 AI 改為 Verified |
| 修改 | 名稱、類型、地址、停留、時間、備註 |
| 刪除 | `window.confirm` 確認；鎖定後為移除提案 |
| 排序與移動 | 當日內上移、下移（44px 按鈕；拖曳為加分項）、移到另一天或移回候選清單 |
| 寫入 | 鎖定前經 security definer 函式（Owner、Companion）；鎖定後以 `applyChange` 的提案操作，批准規則不變。決策 0011 更新：鎖定後 Owner 經 `apply_owner_change` 直接套用 |
| 可行性 | 每次修改後以 `checkDay` 重新檢查，規劃中只提示不阻擋；批准每日時照舊阻擋 |

### S 搜尋加入地點

| 項目 | 規格 |
|---|---|
| 搜尋 | 新增地點畫面的搜尋欄，伺服器以使用者在 Vault 的 Google Maps key 呼叫 Places 文字搜尋；網域依 S-05 經 PR 加入 allowlist（先以瀏覽器確認網址） |
| 保存（D28） | 只保存 place_id；名稱、地址、評分只即時顯示。名稱欄預設為使用者輸入的搜尋字，使用者可修改後保存 |
| 沒有 Maps key | 只顯示手動新增，並提示到設定輸入 key |

### I 行程匯入

| 項目 | 規格 |
|---|---|
| 來源 | 貼上文字：預訂確認信、其他 App 匯出的行程或自己寫的清單 |
| 辨識 | 以使用者的 AI 設定與 key 執行；貼上的內容放在資料區塊（S-03）；輸出經 schema 與 `gateRoleOutput` |
| 寫入 | AI 輸出只是預覽（S-01：AI 不寫入）；使用者逐項確認後以本人 session 寫入為預訂或使用者新增的地點 |
| 敏感資料 | 預覽前以 `buildAiPayload` 處理（S-07）；全名、電話、電子郵件不送 AI |

### B 預訂與清單

| 項目 | 規格 |
|---|---|
| 預訂類型 | 航班、住宿、餐廳、票券、交通、其他 |
| 欄位 | 標題、開始與結束時間、時區、地點、預約碼、備註、關聯項目（可空） |
| 顯示 | 當天的預訂出現在「現在」與「行程」，視為固定活動（Hard Constraint） |
| 預約碼 | 只有行程成員可見；不送 AI、不出現在唯讀連結 |
| 清單 | 每個行程可有多份清單（打包、待辦），項目可指定成員、勾選完成；離線可讀 |

### X 記帳與分帳

| 項目 | 規格 |
|---|---|
| 一筆花費 | 金額、幣別、付款人、分攤成員（預設平均，可自訂金額）、日期、類別、關聯項目或預訂、備註 |
| 匯率 | 行程設定主幣別；其他幣別由使用者輸入匯率（不呼叫外部匯率服務） |
| 總覽 | 總花費、各類別、與基線預算比較 |
| 結算 | 計算誰付給誰（最少筆數），可標記已付款與日期 |
| 權限 | Owner、Companion 可新增修改；Viewer 唯讀；不送 AI |
