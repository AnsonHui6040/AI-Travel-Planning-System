# 0005 使用者確認、差異重大標準與復原

| 項目 | 內容 |
|---|---|
| 狀態 | 已決定 |
| 日期 | 2026-11-23 |
| 決定者 | 使用者 |
| 相關 | 計畫第 2.6 節、第 2.10 節、第 11 節、D10、決策 0004、T08、T10、T10A |

## 確認原則

行程與事實資料的任何改動，都要使用者選擇後才套用。以下三類不改動行程內容，維持自動：

| 變更 | 處理 |
|---|---|
| 新候選加入 Candidate List | 自動 |
| 候選核實狀態更新 | 自動 |
| 已批准項目事實失效（休館、停駛） | 自動標示 At Risk 並通知；重排方案需確認 |

L1 壓縮緩衝與事實資料更正改為需確認，取代決策 0004 與 D10 原有的自動套用。

## 選擇流程

| 步驟 | 內容 |
|---|---|
| 1 | 受影響的項目在行程資訊上顯示問題標記 |
| 2 | 點選後進入下一層，列出已準備好的方案，建議方案排第一 |
| 3 | 同一層提供「請 AI 重新排列」與「維持原狀」 |
| 4 | 「請 AI 重新排列」可以加入不在 Candidate List 的新地點；新方案同樣列出，由使用者選擇 |
| 5 | 使用者選擇前，行程不改動 |

差異不重大時列出一個建議方案；差異重大時列出多個方案，依旅行目標比較時間、成本、體驗、風險。

## 差異重大

影響已批准或已鎖定行程時，下列任一條件成立即為差異重大：

| 面向 | 條件 |
|---|---|
| 時間 | 任一受影響項目的開始或結束時間相差超過 20 分鐘 |
| 固定活動 | 下一個 Hard Constraint 無法準時 |
| 日期 | 項目移到另一天，或影響兩天以上 |
| 成本 | 每人增加 NT$1,000 以上，或超過該項預算的 20% |
| 已付款或已預約 | 需要取消或改期 |
| 體驗 | 必去地點被刪除 |

金額與分鐘數之後可依實際旅行調整，調整時更新本檔與 `packages/core/src/conflicts.ts`。

## 復原

| 項目 | 內容 |
|---|---|
| 範圍 | 可在 Change Log 選任何舊版本復原 |
| 方式 | 建立一個新版本，內容與所選版本相同；原有紀錄不刪除 |
| 權限 | Owner、Companion |
| 版本檢查 | 與其他提案相同，以 base version 比對（SH-04） |
| 復原內容 | 只復原排程（日期、開始、結束時間）。At Risk 屬事實資料，復原不清除，避免蓋掉已知的休館或停駛 |
| 之後加入的項目 | 所選版本之後才排入的項目，復原後改回未排程 |
| 快照 | 每個版本寫入時自動記錄行程所有項目的排程；T10A 之前建立、沒有快照的版本不可復原 |
| 實作 | T10A |
